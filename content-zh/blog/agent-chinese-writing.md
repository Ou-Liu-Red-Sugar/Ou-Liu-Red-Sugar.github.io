让 Agent 帮我写主页上的投资学笔记时，我发现自己经常要充当语文老师. 有些句子单独看都说得通，但是读到下一句时，才发现它用到了前面尚未交代的条件，读者只好自己补出中间的解释. 这样写出来的笔记，还得由我逐处调整，读者才能顺着它理解下去.

起初，我给它设了 Benchmarks，也留下了一些改稿示范，希望它能把这些改法用到后面的文章里. 但是，换了主题以后，同类的句序和衔接问题还是会出现，我仍然得一处处解释. 每次都要重新讲句子和段落怎样安排，我便想让它把组织文章的方法也学起来，以后面对新材料时，能够自己判断该怎样写.

中文写作教材里就有这些讨论. 夏丏尊、叶圣陶的《七十二堂写作课》和《文心》讨论了材料取舍、叙述详略与文章组织，吕叔湘、朱德熙的《语法修辞讲话》则对句法、词序和标点作了具体辨析. 于是，我让 Agent 自己查读相关部分，再带着读到的方法试写、修改，并把能反复使用的办法整理成 skill，供后面的文章继续调用. 具体读过哪些内容、怎样采用，保存在[文献记录](https://github.com/Ou-Liu-Red-Sugar/chinese-writing/blob/main/references/literature.md)中.

## 思想草图

这些方法要用到一篇具体文章里，就得落实为材料的取舍、内容的次序，以及句子之间的联系. 我们把这些安排放在草图阶段，先看文章准备怎样展开，再逐步补足文字. 这和画画很相似：先画草图，确定主要元素及其位置关系，然后在这个基础上补上细节.

最初的第0层草图，只需要想清楚要让读者明白哪些事，以及用什么办法把它们讲明白. 这时可以用流程图安排思想之间的关系，也可以用表格把思想、材料和表达办法对应起来；具体的段落和句子留到下一层安排. 比如，这篇文章要说明标点怎样约束 Agent 的表达，就需要让读者看到一个还没有填满文字、却已经排好标点的草图，再解释它怎样限制后续句子的写法.

## 句子骨架

有了这些安排，我们知道文章要用哪些内容来说明问题，但是这些内容怎样接成段落、每一段里的话怎样往下说，还没有确定. 到第1层草图，就要确定各节、各段分别讲到哪里，并直接写出起句和衔接句，用关联词与标点安排中间内容的关系. 还没有展开的事实、例子或推导，可以先用含义明确的占位标出来. 例如，一段数学讲解刚结束两个取值的例子，准备推广到一般情形，可以先排成这样：

> 前面的例子只用了两个取值，现在把它推广到有限多个取值. 设〔变量及各个取值〕，并以〔各取值的概率〕作为权重，则〔这些取值的加权平均〕可以写为：〔公式〕.

虽然括号里的内容还没有写出，但是前后两句话怎样推进，已经在这里安排好了. 前一句接住刚讲完的例子，把讨论范围扩大，用句号结束这次转场；后一句用“设……，并……，则……”连续引入对象、权重和要表达的量，再用冒号引出相应公式. 填充这些位置时，Agent 就要沿着这次设定的顺序组织内容，把专业信息接进已经确定的句式.

## 专项修订

但是，排好了句子，还需要判断这些安排放在整篇文章里是否合适. 有些地方的内容已经齐全，只是转折没有写明，补上“但是”就能让关系清楚一些；如果前后少了一项理由，加上“于是”也不会把它补出来. 例如，开篇如果只写“我还得反复解释，于是让 Agent 去读教材”，两件事之间仍然跳了一步. 这里还需要交代我希望它学会组织文章的方法，再说明教材能够提供哪些帮助，读者才容易明白这个选择的来由. 发现这样的缺口，就要从材料中核清所需的理由，将它写进草图，并调整前后句的次序与连接，再连起来读一遍，看这项解释是否已经接上.

除句间衔接以外，我们还会分别检查材料详略和必要限定. 与主题无关的旁支可以删去，读者理解当前问题所需的内容则要写足；删改这些文字时，也要留意判断的条件是否仍然完整. 防御性措辞尤其需要这样检查：空泛的谨慎表态可以删去，但是成立条件和来源身份要保留，并贴着相应判断写. 比如，讨论单一产品时，“销量不变时，提价会增加收入”已经交代了条件，后面再补“仍需结合具体情况，不能一概而论”，就没有增加信息；删去这句提醒，前面的“销量不变”仍然要保留.

每次修订都要回到被指出的地方，看问题是否已经在文字中解决. 经过这样的修改，段落、句序、必要解释和标点逐渐确定下来，最终草图也就越来越接近正文. 剩下的空缺只需填入意思和位置都已确定的局部文字，一处可能只有几十个字，已经不需要填充者重新组织整段话. 到这个时候，才单独安排正文填充，让 Agent 按已经确定的意思和句法位置补齐文字.

## 复用与校准

这套过程也可以分工完成. 由一个 Agent 主持写作，把当前草图交给 Chat 或另一个 Agent 审读，请它指出具体的问题和改法. 主持者收到意见后，先判断哪些意见应当采用，再修改对应的文字，核对修改后的上下文，并保存修改前后的草图. 留下来的既有这篇文章的改稿，也有问题出现在哪里、为什么这样改的记录，下一次遇到相近情形时，便有材料可以参照.

方法保存下来以后，还要看它换一份材料能不能继续起作用. Benchmarks 就用来检查这一点：让 Agent 用新的材料写作，再请另一位执行者只依据成稿回答理解题，例如文中为什么采用某种办法、某个判断在什么条件下成立. 如果回答所需的理由或条件无法从正文取得，就回到相应的草图，检查它是在安排内容时被漏掉了，还是写入句子时没有交代清楚，再修正对应的写作办法.
