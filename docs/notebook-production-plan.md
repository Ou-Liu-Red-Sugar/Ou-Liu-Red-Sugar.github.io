# 投资学笔记：五领域 Chat 写作与接入计划

版本：2026-09-21。范围是完成现行大纲的内容生产安排：五个领域作者分工、按批次新建 Chat、实际文献阅读、分组规划、Codex 确认、成组写作与本地接入。正文标准以 [写作规范](notebook-authoring.md) 为准，节点范围以 [详细大纲](investment-notebook-outline.md) 为准。此计划不将准备、派题、已读、成稿或页面验收混为一项完成状态。

## 1. 分工与执行单位

五个一级领域分别安排作者与文献研究职责，按具名成稿或审校批次新建 Chat。Codex 是总编辑和实现者，使用正式术语、来源和当前稿保持领域连续，并统一确认跨领域接口。公司库由 Codex 维护公共身份与研究快照，相关领域作者交出实际使用的材料和解释。

使用 Chat 模式。成组正文使用界面实际可选的 6 Pro；文献补读、后续规划、审校与修改建议使用 xhigh，发送时记录实际模型与档位。用户于 2026-09-21 指定本轮 6 Pro 尽量控制在 20–30 次；以 25 次排程、30 次为本轮上限，调用及失败/续写均记入生产记录。首轮五次文献规划已经使用 6 Pro，纳入预算；之后不为审校另用 Pro。文献搜索与阅读是作者任务的一部分，允许并要求按需自行搜索，不把已有 82 项资料当作封闭书单。工具或模式不能取得所需材料时，先取得可读正文；不能用模式名称或模型自报代替阅读。

领域总规划与每次成稿分开：先读领域核心材料及首组承重文献，交整个领域的初步组序；随后每组继续补读完整相关材料、细化计划并获得 Codex 确认。没有必要在第一条消息中通读整个领域所有教材，也不能靠读一遍目录就安排所有正文。

现有 127 个节点分成 47 个有主题联系的内容组，下面给出起始排程。内容组不等于模型调用：xhigh 可一次补读并规划多个相关组，经 Codex 逐节点确认后，合并为一次 Pro 成稿任务。按首轮 5 次 Pro 规划加约 20 次成稿安排，通常每次覆盖 4–8 个学习节点，短参考可随组；复杂行业分支和证明按实际长度调配，在 30 次总上限内保留续写或实质重写余量。使用完整节点文件交付，不能压缩教学来挤进一次屏幕回复。成稿范围未获确认前不边读边擅自扩写。

会话边界统一按 [写作规范第3节](notebook-authoring.md#3-chat-协作与上下文) 执行：跨成稿批次或更换职责即建立新会话，完整当前稿、文献单元、冻结输入与未决问题随文件交接。独立审校使用新 Chat；共享项目不称隔离盲审。新的阅读、计划和审校仍用 xhigh，切换会话不增加 Pro 配额。

## 2. 先实际读 reference，再规划与写作

这里的“阅读”明确指教材章节、讲义正文、论文的相关完整单元，以及财报、合约、数据说明等原始材料。大纲、模板和资料索引用来限定任务及定位原文，不抵扣文献阅读。

每组按以下顺序推进：

1. **搜集并阅读。** 作者查已有来源并主动搜索补充，实际取得所需正文。经典材料负责定义与基础推导，当期原件负责规则和案例，近年研究用于检查现代认识与实践；各自记录版本和作用。检索宽度按内容需要，不用固定篇数凑数。
2. **交阅读报告和分组写作方案。** 给实际读到的章、节、页或命题，概述对本组真正有用的内容、条件与分歧；同时提交节点顺序、学习产出、真实案例、承重推导、图与互动、练习、引用关系及材料缺口。没有正文的资料只作候选。
3. **Codex 核对并确认。** 我核原件是否足以支持计划，检查定位、数学/金融条件、现代制度、教学密度与跨组接口。采用、需要修改及暂缓部分写入同一批次记录。需要修订时一次合并给作者，不用轮番零碎追问。
4. **6 Pro 成组写作。** 确认消息明确批次、节点、输入版本、案例、允许范围和待补限制。作者先形成组内连续叙述，再按固定 ID/模板拆为可独立阅读的词条；共同定义、数据与案例只维护一份。新发现会改变结构或关键结论的材料先交修订方案，普通补引直接记录即可。
5. **xhigh 审校与必要返修。** xhigh 根据完整稿及对应原文检查逻辑、假设、教学任务和修改点；Codex 另核承重原件、规则、证明/推导及计算，并承担采用决定。逐篇向作者追问“读者只读完这个词条，真的能学明白吗？”，要求指出缺口并改正文，而非只交自我评分。零碎修改由 xhigh 与 Codex 完成；确需 Pro 实质重写时合并问题并计入总额。
6. **接入与实际验收。** Codex 将采用内容接入唯一正文源，实现交互、内联引用、图谱和 Agent 导出，核对静态说明、公式断行、数字排版、手机及键盘使用。交互需要验证输入和联动结果；文稿通过不等于网页已完成。

以上确认由 Codex 承担，属于用户已经指定的编辑流程；每组普通取舍不重复向用户请示。改变五领域边界、投资方法或大幅扩展任务时，才提出具名问题及影响。

## 3. 作者必须交回的阅读与规划内容

首轮和每组规划都使用简短结构化回单，长篇原文无需抄回。

| 内容 | 必须说明 |
|---|---|
| 实际读取 | 作者/机构、标题、URL或文件、版本/期间、实际章页范围、正文是否完整取得；此前索引中的已读不能冒充本 Chat 已读 |
| 采用与分歧 | 哪些定义、机制、命题、实证结果或规则进入哪些节点；作者主张和教学采用分开；选择来源的理由 |
| 本组结构 | 主 topic、节点 ID、模板、完整学习任务、组内叙述、各篇开头承接与结尾去向 |
| 案例及计算 | 真实对象、材料时间和单位、原表/条款定位、必要输入、可重建步骤；共享数据使用同一版本 |
| HTML 方案 | 读者能操作什么、操作改变什么、应观察什么；图的输入/公式/输出、静态等价解释 |
| 理解检验 | 能独立解释或重建的任务、迁移题及解析安排；基础已知者直接进入重点 |
| 引用与图谱 | 本组定义的主归属、先修、调用、推导、实例与来源边；未成稿目标保留计划身份 |
| Agent 包 | 公开可读的必读原文、完整阅读单元、教学 Prompt 的任务与反馈标准；本地资料另标可访问条件 |
| 缺口与决策 | 未取得原件、尚未核条件、报价不足及影响；只提出会改变采用的问题 |

允许作者否定现有某条骨架的具体安排，但须先用资料与教学理由提出修改；不能在成稿里悄悄改分类、方法或研究时期。

## 4. Codex 的确认标准

确认依赖可检查的材料与计划：引用能定位；实际读取范围足够；概念和机制理由讲通；数学条件与金融单位准确；实例确实体现行业/合约差异；一个完整学习任务有足够深度；交互承担解释职责；跨领域术语与共享数据一致。

来源存在并不自动证明使用正确。我对改变教学结论的关键来源和计算实际复核；普通重复引用复用同一已核结果。计划审阅不预先宣称完成正文审阅。遇到实质错误，退回受影响节点和共同输入，已接受的无关节点继续。

每组首先交一轮完整计划，必要时给一次合并修订；仍有承重缺口时登记具体问题和解决动作。这个安排约束重复沟通，不允许为了结束轮次接受错误。

## 5. 分阶段推进

**阶段 A：五个领域分别完成阅读与领域规划。** 确認五个新 Chat 的实际身份和读取入口，分派各自交接包。各 Chat 先读核心 reference 与首组材料，交本领域拟定组序及首组详细方案。Codex 合并跨领域关系与共享案例，再逐组发出成稿确认，不要求所有领域一起等待最慢的一项。

**阶段 B：五组样板，校准教学和页面。** 首组为 M-A、BF-A、EI-A、P-A、QT-A。BF-A 先做共同结构和两种差异明显的行业，材料就绪后补其他分支。首组优先每领域一次完整交付；需要续写时记入预算。Codex 先把代表节点接入页面，xhigh 审校文稿，依据实际阅读结果调整本批余稿和后续交互。样板验收不能靠作者自评。

**阶段 C：按接口推进成组写作。** 市场先补期权、期货与永续的契约材料，投资线接策略和对冲；企业与行业线形成可复用的业务、利润、资本和证据材料，投资线接业务估值；数学线提供实际需要的定义、验证与实验。五个领域继续各自的阅读路线，生产次序不成为读者唯一学习路线。

**阶段 D：补齐专题和研究分支。** 完成其余工具、行业分支、现代研究与严谨证明，修正全域导航和引用。每批同时带上图谱关系和 Agent 包，不在最后另补两套内容。

**阶段 E：整体检查。** 按五条路线实际走读，核跨页条件、公司研究时间、引用预览、练习解析、Agent 原文可读性及中英配对。已有英文数学笔记保持独立；本次投资词条默认先形成中文完整稿，英文在明确配对与采用后逐组制作，不能把一套中文节点记成双语完成。公开发布仍是独立行动。

以下组序是可执行的起点，作者实际阅读后可有据调整。调整保留节点唯一归属，并记录理由。

## 8. 文稿交付、回收和网站接入

规划回单使用一个 JSON 代码块，包含 task_id、domain、batch、phase、input_versions、readings、entry_plans、shared_inputs、open_issues。记录支持范围和采用依据，无需逐字思考过程。内容长时先交首组，其他组列安排及待补资料。

正文按节点 ID 和 T 模板交完整 Markdown，优先实际可下载的节点文件；没有文件输出时，每个节点用一个完整代码块，另附短 JSON 索引列节点、来源、案例、关系、交互和修改。长正文不强行塞进一个巨大的转义字符串。数学采用 LaTeX 并按逻辑自然断行，原始表保留单位和期间。

Codex 通过内置浏览器回收实际文件或代码块，保存作者原稿和实际回收方式。页面文本提取只声称提取；手工修订保留采用说明。沿现有协作方式优先让 Chat 使用 codex-with-chatgpt 读取具名本地文件；连接映射和实际读取都要核实。普通读取故障按已授权流程修复，仍不可用时只打包当前批次必要材料上传对应 Chat，并核实它读到的范围。不得因“文件已传”就标记“文献已读”。

内部估值方法、研究和历史 TeX 仅取本组需要的具名部分。不得将整个私人研究库、账户或无关项目一起发出。公开 Agent 包使用公开原文或可公开的本站正文，不能保留无法访问的本地盘符作为唯一 reference。

接受后由 Codex 将内容写入现行唯一正文源 notebook/entries，并统一调整实际受影响的字段和生成器。初稿属于交付记录，不成为第二套持续维护正文；HTML、内联预览、图谱和 Agent 导出共同消费正式内容。

## 9. 状态、成本与恢复

每组依次记录：待阅读 → 阅读与规划中 → 待 Codex 确认 → 可成稿 → 初稿已回收 → 返修/内容已接受 → 已接入 → 页面已验收。每项状态须有真实回单或文件依据；新增资料读取、模型设置与会话 URL按实际发生记录。

进度按已接受的完整节点、已完成的行业分支与页面验收报告；短参考单独计数。五个会话可以保持独立，但同时生成的数量根据实际可用性和回收能力调整，开始以 2–3 组重叠生成，余下会话继续阅读和规划；不将会话数量等同于平台并发保证。

先用首轮实际记录校准阅读、生成、返修、实现所需时间，再估剩余工作量。47 组是任务拆分，不是保证的 47 次调用，也不在未运行前承诺固定总时长。实际用量若记录，注明共享账户和读取时点。

恢复从 [生产记录](notebook-production-state.json) 的对应会话、批次及最新已回收文件继续；不因等待超时重新派题。进入下一批时作者读当前版本的 reference 与本组输入。整个计划已获用户要求制定，普通编辑确认由 Codex 完成。
