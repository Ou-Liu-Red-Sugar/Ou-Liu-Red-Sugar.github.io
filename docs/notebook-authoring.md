## 导航与大纲

`notebook/learning-plan.json` 是主题节点、关系、规划词条及推进顺序的唯一现行源。生成器据它更新 `data/notebook_map.json` 和本项目的写作大纲，避免分别维护网页上的词条标题和编辑大纲。网站导航显示主题与直接关联；正式文章标“已写”，用户指定的大纲占位页标“大纲”，其他规划词条标“待写”。大纲页不计入已写篇数。

图谱区分学习衔接、知识支持、经济联系、决策用途和研究反馈。实际先修在各词条的 `prerequisites` 中另列，反馈关系可以有回路，不据图谱箭头强制顺序。顺序阅读独立放在 `/zh/notebook/reading-route/`，首页保留入口，文章内的路线链接指向该页；页面仍沿同一计划源生成起步顺序、衔接与后续阶段。阶段表是推荐写作顺序；读者完成基础判断后可以直接进入 Agent 研究，合约专题按用途选读。

调整大纲时先保存实际旧版，再修改计划源及受影响的标题、先修、关系和推进顺序，运行生成器同步现行输出。计划中的来源和实例是取材安排，不代表已经完成本篇原件核实。

## 单篇写作

先全文读取 [用户写作要求](writing-requirements.md)，再通过 [主页中文写作接入](chinese-writing-workflow.md) 使用当前 `chinese-writing` skill。通用 workflow 负责第0版思想与呈现安排、第1版段落与标点骨架、后续修订和正文。取材与深挖的时点、审读分工和验收标准均沿该流程。

同一时刻推进一篇文章。每天约5篇是写作目标，按完整定稿计数，并根据实际难度和返修调整。用户要求监督时，到指定版本就交回；正文和下一篇分别沿实际授权继续。定义、实例、推导和必要条件按文章要解决的问题安排，不套用旧词条章节清单。草图和反馈保存到本篇 `docs/production/<任务>/`，注明当前版本、实际输入、采用情况和停止点；该目录是本地工作记录。

图表和补充说明在编排时确定用途。交互图表说明要比较哪些条件、展示什么过程、读者操作后看见什么；简明版与详细版的内容取舍沿[写作要求第13节](writing-requirements.md#13-列表标题表格与流程图)。同一段以 `span[data-text-versions]` 包住连续文字，在语义对应处用 `span[data-text-detail]` 保存完整补充，句末放带 `data-text-version-toggle` 的空按钮，类名为 `text-version-toggle`，初始带 `hidden`。页面显示“详细版／简明版”文字入口，补充文字以淡色插回原句；无脚本、打印和全文导出均保留详细内容。来源脚注仍用于引用定位。规划大纲不能代替本篇实际草图和审读。

## 正式内容与生成

`notebook/entries/*.json` 是正式词条源，`notebook/catalogue.json` 登记已写内容实际需要的分类、来源和阅读路线。规划词条保存在学习计划中。用户指定大纲占位页时，在对应计划条目的 `outline_page` 中保存 `slug` 和 `sections`，由生成器创建仅含大纲的页面；不把大纲登记成正式正文或教学包。NB-A01已在原占位页地址接入完整本地稿。

新中文词条以 `node_id` 精确对应计划编号，例如 `NB-A01`，并采用独立的正式源 `id` 与网页 `slug`。已有大纲页的词条沿用它的 `slug`，正文完成后在同一地址替换大纲。生成器从实际正文或明确生成的大纲页取得链接，标题相似或仅有计划不使链接生效。条目字段沿现有生成器的数据格式填写，存储格式不规定正文的章节与句法。

`notebook/notation.json` 保留已有符号与单位约定，中文说明使用中文标点。新正文保持术语、期间、单位和分母一致；来源须能定位到实际采用的材料。更新正式源后运行 `python tools/build_notebook.py`，由它生成双语内容目录、搜索数据、关系数据、Markdown 正文、LLMS 索引与全文汇总，以及 Agent 参考材料和简短开课指令，避免分别修改生成副本。

网页“教学 Prompt”复制的是学习者第一人称的开课请求、[Agent 教学指南](../content-zh/notebook/teaching-guide.md)和本篇 HTML 正文的绝对入口，以及少量本篇讲解参考。先读指南，再按学习者当前问题、目标和理解程度选取正文及材料。复制指令已经确定篇目；未附具体问题时，在本篇范围内问清这次想弄懂什么，并等待回答；已有具体问题时直接接着讲。通用的讲述方式、教学工具选择与反馈方法集中在指南中，复制文本不重复这些规则。完整正文、实验和数据从网页按需读取。

每篇正式源的 `teaching` 字段保存少量易混点、可用例子及精选来源编号，生成器据此给出提示和文献入口。这些材料不构成必须讲完的清单；当前解释依赖原件中的数字、规则或假设时，再核相关段落，无需首讲前读完全部文献。[教学基准与示范](../content-zh/notebook/teaching-benchmarks.md)保存不同学习需要下的案例与采用标准。测试自主选择工具时，学习者输入不指定表格、图或实验；实际示范、测试回复和用户评价分别记录，不能从格式符合推断教学效果。

完整 Agent 参考材料保留正文、作者的事实口径说明、实验输入与来源定位，仍通过 `/agent/<语言>/<slug>.md` 下载；正文 Markdown 继续通过 `/llms/<语言>/notebook/<slug>.md` 读取。作者 `prompt` 作为参考材料中的范围说明保存，学习者本轮请求决定课堂任务。读取日志属于可选记录字段，不是开课产物。教学指南与基准页是独立网页，不登记为正文词条，也不由词条生成器覆盖。本地预览的公开链接只能取得已发布内容，未发布稿可按开课指令中的回退方式粘贴所需段落；以粘贴全文完成的测试与读取公开网页的测试分别记录。

本地核对依次使用：

1. 在 `tools/` 运行 `python -m unittest test_notebook_learning_plan.py test_build_notebook.py`，检查计划、先修、真实文章映射和生成约束。
2. `node --test tools/notebook-math.test.mjs tools/notebook-number-format.test.cjs` 检查共享计算和数字显示。
3. 将 Hugo 输出到新的本地临时目录，再用 `python tools/check_notebook.py --build-dir <输出目录>` 核对页面、引用、Agent 导出与内部链接。避免覆盖 `public/` 中已有成果。

新增文章还需按其内容核对事实、推导、页面和实际交互；通用构建检查不能代替写作验收。本地完成后交付当前篇及过程入口，发布按用户明确授权执行。
